# Stage 4 自测报告：IEEE 粘贴识别

测试日期：2026-09-17　测试环境：Node 22（识别引擎）、Playwright + Chromium（页面交互，桌面 1200px 与手机 375px）

**结论：识别引擎 38 项、页面端到端 44 项，共 82 项全部通过。**全部样本为合成数据。

## 1. 开工前发现的仓库问题（需要处理）

GitHub 上 `main` 分支的 `index.html`、`README.md` 和 `docs/` 下三张截图在 2026-09-17 的几次网页上传后都变成了 **0 字节**，线上页面因此是空白的。仓库里最后一个完整版本（2026-09-16）是 **Stage 2**，没有 Stage 3 的粘贴识别代码。

本阶段因此以 Stage 2 为基础，**按 Stage 3 的验收规格重建了 Elsevier 粘贴识别**，与 IEEE 识别合为一个模块。重建时对应的规格如下：

- 追踪页、EM 列表、单个状态词三类粘贴；
- Revise 让用户选大修小修；
- 记住自定义说法；
- 按稿号（忽略 R1）→ 标题 → 新增的匹配顺序；
- 追踪链接选填且不读取。

Stage 3 当时的 3 个合成样本不在仓库里，回归测试改用同类的 3 个重建样本（E1–E3）。**如果你本地还有 Stage 3 验收版的 index.html 或样本，建议用原样本在新页面上再粘贴一遍确认。**

## 3. 测试中发现并已修复的问题

1. **Author Portal 卡片的期刊名错位到上一张卡片。** 自动测试没有发现，是查看 375px 截图时发现的：卡片上期刊名在状态上方，被划进了前一条记录的范围。已改为优先在记录开头上方 3 行内找期刊名；ScholarOne 页面顶部的期刊名适用于每一行。新增 T5d、T5e 防止回退。
2. **只有「不导入」结果时仍显示「应用」按钮。** 切换到结果页的函数在渲染之后又把按钮显示出来了。已调整调用顺序，由 UI-6a 覆盖。
3. **决定词整格被当成标题。** 例如 ScholarOne 的「Reject/Resubmit: Major Revisions Required and External Reviews Needed」比真实标题还长。已排除包含状态说法的单元格，由 T3 覆盖。
4. **状态名重复显示**（「已接收 Accepted 已接收」）。说明文字与状态名相同时不再重复显示。

## 4. 实现与方案的差异

- **撤稿**：预置状态里已有「已撤稿」，Withdrawn 直接对应，没有触发确认项第 3 条。
- **编辑处理阶段**：没有「编辑处理」「等待决定」这两个预置状态，因此编辑处理对应「已投稿」，等待决定对应「审稿中」。原始英文说法保存在论文详情的「最近识别」里，不丢失细节。
- **数据版本**从 2 升到 3，新增三个字段：
  - `trackingUrl`（追踪链接）；
  - `lastRecognized`（最近识别：说法、来源、日期）；
  - `pasteAliases`（记住的说法）。

  旧数据和旧备份打开时自动补齐字段；备份、合并恢复、覆盖恢复都带上记住的说法。删除自定义状态时，一并删除指向它的说法。
- **页面布局**：顶部栏新增「粘贴识别」按钮。手机上「＋ 添加论文」缩写为「＋ 添加」，保证三个按钮在 375px 内放得下，且高度不小于 44px。

## 5. 已知限制（测试版）

1. **没有真实页面样本。** IEEE 两个系统复制后文字的确切排版未经证实，合成样本依据公开文档的字段编写。其中 ScholarOne 的「ADM: 姓名」行、Author Portal 卡片的「Manuscript ID:」写法都是假设。引擎已兼容「状态在稿号前 / 后」「单元格拆成多行」「卡片不显示稿号」几种排版，但真实页面仍可能有差异。
2. **Author Portal 状态粗**，这是系统本身的限制，页面上已提示。
3. **识别不到时的兜底**：
   - 某期刊自定义的说法不在词典里：用「记住这个说法」处理。
   - 稿号格式不是「字母开头、至少两段、其中一段 4 位以上数字」：稿号识别不到，会退回按标题匹配。
4. **日期**：Editorial Manager 的 01/02/2026 按月/日/年解析；第一个数大于 12 时按日/月/年解析。新增论文前会显示日期供核对。
5. **浏览器**：只在 Chromium 内核上跑过自动化测试。
